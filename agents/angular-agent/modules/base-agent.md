# Base workflow

1. Scope the task to a project and a user-visible outcome.
2. Read repository guidance and trace the current entry point.
3. Specify the expected behavior, failure cases, and acceptance checks.
4. Add or adapt a focused test and confirm it fails for the intended reason when practical.
5. Implement a small change through the project's existing boundaries.
6. Run the focused tests and relevant lint/build checks.
7. Review the diff for regressions, accessibility, and compatibility.
8. Hand off the changed behavior, evidence, and any unrun checks.
